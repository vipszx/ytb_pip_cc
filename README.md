# YouTube 字幕画中画

一个纯前端的 Chrome 扩展（MV3）。在 YouTube 观看页点击一个入口图标，弹出一个**极小的系统级置顶窗口**，里面**只有字幕、没有画面**；窗口内可以直接调倍速、调字号、播放/暂停、开关字幕。

## 功能

| 能力 | 说明 |
| --- | --- |
| 字幕画中画 | 使用 Chrome 的 Document Picture-in-Picture API 弹出独立小窗（默认 420×132），只显示字幕，最多三行、放不下自动缩字号，切换回原标签页也不会被关闭 |
| 置顶最前 | PiP 窗口天然位于所有普通窗口之上，可拖到屏幕任意角落，一边看别的软件一边看字幕 |
| 倍速控制 | 小窗内 `−` / `+` 按 0.25 步进，点击倍速数值循环 0.5→0.75→1→1.25→1.5→1.75→2，直接作用于页面 `<video>`，与画面完全同步 |
| 音量控制 | 小窗内 `−` / `+` 按 10% 步进，点击音量数值静音 / 恢复；在 YouTube 播放器里改音量，小窗数值也会跟着变 |
| 字号控制 | `A−` / `A+` 按 2px 步进（12–40px），跨视频、跨会话记忆 |
| 字幕来源 | 默认下载视频的**完整字幕轨道**（timedtext/json3），按「间隔 + 句末标点」合并，**歌词式展示**（当前句高亮居中，上句/下句小一号压暗），时间轴精确、按播放进度同步；可在 popup 里**手动切换成 DOM 模式**（抓取播放器渲染的字幕，兼容性最好）。接口模式拿不到轨道时自动回退到 DOM。**支持自动翻译/任意语言** |
| 点击复制 | 点击字幕文字即可复制当前句，屏幕中央提示「已复制」 |
| 播放控制 | 小窗内播放/暂停；`CC` 按钮可直接开关 YouTube 字幕 |
| 自动开字幕 | 打开小窗时若字幕未开启，自动点击 YouTube 的 CC 按钮（可在 popup 中关闭） |
| 降级方案 | 浏览器不支持 Document PiP、或用户激活丢失时，自动改为页面内浮动小窗，界面与功能完全一致，额外支持拖拽 |

## 安装

1. 打开 `chrome://extensions`
2. 右上角开启「开发者模式」
3. 点击「加载已解压的扩展程序」，选择本目录 `ytb_pip_cc`
4. 需要 **Chrome 116 及以上**（Document Picture-in-Picture API）

> 图标在 `icons/`（16/32/48/128 PNG）。想改样式可运行 `python tools/make_icons.py` 重新生成（需要 Pillow）。

## 使用

1. 打开任意 YouTube 视频
2. 在播放器**右下角控制栏**找到字幕小窗图标（在设置齿轮左侧），点击即弹出置顶字幕小窗
3. 再次点击同一图标，或点小窗里的 `✕`，即可关闭
4. 点击浏览器工具栏的扩展图标可以调整默认字号、默认倍速、**显示模式**（歌词 / 字幕）、**字幕来源**（接口 / DOM）、是否自动开字幕，也可以从这里尝试打开/关闭小窗

### 字幕来源：接口模式 vs DOM 模式

| | 接口模式（默认） | DOM 模式 |
| --- | --- | --- |
| 取数方式 | 复用播放器自己的 `timedtext` 请求（带 `pot`）取整段轨道 | 读播放器当前渲染的字幕行 |
| 显示 | 整段到手，**一句一句**按时间轴显示 | 跟着 YouTube 官方节奏走 |
| 前提 | 字幕要在页面上显示过一次（会自动开 CC） | 只要页面有字幕即可 |
| 适用 | 推荐；抖动最小 | 接口被 YouTube 限制时的保底方案 |

切换后立即生效，不用重开小窗。

### 显示模式

popup 里可切换两种模式，切换后立即生效：

| | 歌词模式 | 字幕模式 |
| --- | --- | --- |
| 布局 | 上两句 / 当前句 / 下两句，共五行 | 只有当前句 |
| 上下文字号 | 0.88em（只比当前句小一点） | — |
| 当前句 | 最多两行（其余高度让给上下文） | 最多三行，字号更大 |
| 窗口高度 | 190px（五行需要空间） | 132px |
| 滚轮 | **可上下翻看整段字幕** | 无 |
| 适用 | 想看上下文、想回头看漏掉的句子 | 只想看当前这句 |

歌词模式下五行会把 132px 的字号压到 13px 左右，所以歌词模式开的小窗是 180px（`PIP_HEIGHT_LYRICS`）。Document PiP 窗口创建后改不了尺寸，**切换模式要重开小窗才换新高度**；页面内浮动小窗是普通 DOM，切换时会自动改高度。

**歌词模式的滚轮翻看：**

- 鼠标在小窗里向上/向下滚，就往前/往后翻一句；翻看时**以进入翻看时的位置为锚点**，视频继续播放也不会把你正在看的内容带走
- 停手 **6 秒**后自动回到当前播放位置（`LYRIC_BROWSE_MS`），也可以继续滚着看
- 翻看需要整段列表，因此**只在接口模式可用**；DOM 模式只能看到播放器已渲染的行

五行共有同一个字号基准：当前句 1em，上下句 **0.88em**（只小一点，靠颜色和位置区分主次）。

长句的处理顺序是 **先保字号、再收行、最后才缩字号**——这是 `ui-template.js` 的 `fitText()` 的核心：

1. 用用户设定的字号算出当前句能占几行
2. 放不下就收起外侧上下文行：五行 → 三行 → 一行
3. 收到只剩当前句还放不下，才二分缩小字号

因为字号是五行共用的，直接缩字会让整块（包括上下文）一起变小、看起来像「字体突然变小」，所以改成让行数来吸收长句。190px 高度下，20px 字号最长能完整显示 60 字的句子且**完全不用缩字号**。

上下文行为空时 `.ytbpip-ghost:empty` 会隐藏它、不占位，高度预算里也不算——所以第一句（没有上文）时当前句能占满。

想改成上下各一句（三行）或各三句（七行），改 `content-isolated.js` 的 `LYRIC_CONTEXT` 即可。

### 小窗工具条

```
[▶] [−] [1.5×] [+] │ [−] [80%] [+] │ [A−] [A+] [CC] [✕]
```

- `▶/⏸` 播放暂停 · `−/+` 倍速微调 · `1.5×` 点击切换常用倍速
- `−/+` 音量微调（10% 一档）· `80%` 点击静音 / 恢复，静音时显示为「静音」
- `A−/A+` 字号 · `CC` 字幕开关（开启时高亮）· `✕` 关闭

字幕开关状态由 `CC` 按钮自己的选中态表示。窗口拖窄时会依次收起音量组（<348px）、字号按钮（<300px），倍速和播放控制始终可见。

## 已知限制

- **首次打开必须由你亲自点击页面上的按钮**：Document PiP 要求「用户手势」，从 popup 转发消息有时会被浏览器判定为缺少激活，此时会自动降级为页面内浮动小窗。
- **整页刷新/跳转到别的网站会关闭小窗**：PiP 窗口依附于打开它的那个页面。YouTube 内部的视频切换（SPA）不会关闭小窗。
- 字幕优先来自视频的完整字幕轨道；轨道拿不到时回退到 YouTube 渲染的字幕层，因此**视频本身必须有字幕轨道**，纯音乐/无字幕视频不会有内容。视频打开期间在 YouTube 菜单里切换字幕语言，需要重开一次小窗才会同步。
- 若你改用 YouTube 原生菜单切换倍速，扩展会自动采纳你的选择，不会强行拉回。
- 广告播放期间 YouTube 会强制 1×，扩展不干预；广告结束后会恢复你设定的倍速。

## 常见问题

**点了图标没反应？**
先确认当前是 `/watch` 视频页，并刷新一次页面（安装/更新扩展后必须刷新已打开的标签页）。

**小窗里一直显示「字幕未开启 · 点 CC 开启」？**
点小窗里的 `CC` 按钮，或在 YouTube 播放器上手动开字幕。部分视频没有字幕轨道。

**小窗太小/想更小？**
拖动 PiP 窗口边缘即可缩放，布局会按比例自适应；也可以用 `A−` 缩小字号让排版更紧凑。

## 架构

```
                 ┌──────────────── 首选 ────────────────┐
YouTube DOM ──> isolated world（字幕/倍速/设置）──requestWindow──> PiP 窗口
                 │        │  document CustomEvent        │
                 │        ▼                              │
                 └──> MAIN world（备选开窗 / 指令转发）──→ 失败时
                          │
                          └──> 页面内浮动小窗（最终降级）
```

- **开窗双保险**：isolated world 优先直接调 `documentPictureInPicture.requestWindow()`；若该 world 取不到 API 或调用被拒，再通过 `document` 上的 CustomEvent 请求 MAIN world 代为开窗；两者都失败则 1.5 秒内降级为页面内浮动小窗。
- **单向数据流**：isolated world 负责全部数据采集与设置持久化，窗口宿主只负责渲染与回收指令。
- **MAIN world 必须在 `document_start` 注入**：用 `document_idle` 时它不会注入（实测如此），而字幕链路依赖它。

### 完整字幕轨道是怎么拿到的

YouTube 对 `captionTracks[].baseUrl` 加了门禁：直接请求（哪怕带 `&fmt=json3`、同源、带 cookie）一律返回 **HTTP 200 + 零字节 body**。播放器自己会额外带上 `pot`/`potc`（proof-of-origin token）等参数，我们无法自行签发。

做法是复用播放器的请求：MAIN world 在 `document_start` 时包装 `window.fetch` 与 `XMLHttpRequest.prototype.open`，记下播放器自己发出的 `/api/timedtext` 地址（含 `pot`）。整条链路只有三步：

1. isolated world 发 `TRACK_REQ` 向 MAIN world 索取地址
2. MAIN world 回一条**属于当前视频**（匹配 `v=<videoId>`）的拦截地址
3. isolated world 把它统一成 `fmt=json3` 后拉取、解析成时间轴（`track-cues.js`）

**因此字幕要先在页面上显示过一次**，`pot` 才会存在——这就是「自动开字幕」（`autoEnableCC`）的意义。首次没拿到时会延迟 1.8 秒再问一次，等播放器把字幕拉出来。整轨到手后不再有「一个字一个字蹦」的问题。拿不到时回退到 DOM 取词，此时用整句上屏（`caption-tracker.js` 的 `MODE = 'sentence'`）来抑制抖动。

## 排障

在 YouTube 页面按 `F12`，Console 里过滤 `ytbpip` 可以看到完整链路日志（`[ytbpip·iso]` / `[ytbpip·main]`）。另外可直接在 Console 执行：

```js
__ytbpipDiag
// { api: true, requests: 1, opened: true, lastError: "" }
```

- `api: false` 表示当前浏览器不提供 Document Picture-in-Picture（需要 Chrome 116+，且非受限环境）
- `lastError` 会给出 `requestWindow` 失败的具体原因（如 `NotAllowedError` 表示缺少用户手势）
